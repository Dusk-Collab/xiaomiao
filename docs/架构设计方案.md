# 扫码点餐小程序 · 架构设计方案

对标蜜雪冰城 / 塔斯汀的门店扫码点餐系统。顾客端小程序 + 独立商家后台 + 全托管云端。

---

## 一、给不懂技术的你：一句话说明白

顾客扫桌上的二维码 → 进小程序点单 → 微信支付 → 拿到取餐码；
你的手机/电脑后台"叮"一声播报"您有新的订单" → 你手指一滑标记完成 → 顾客手机自动提示取餐。

所有代码和数据都放在腾讯的机房，**不在你的电脑上**。你电脑关机、断网、卖掉，顾客照样能正常点餐。

---

## 二、必须先知道的 4 个现实约束

### 1. 微信小程序里不能接支付宝

微信生态内只允许微信支付，接第三方支付会被直接封禁小程序。这是平台规则，没有技术手段可以绕过。

- **建议**：一期只做微信支付，覆盖门店场景 90%+ 的用户
- **想要支付宝**：需要额外开发一套支付宝小程序（代码可复用约 70%，但要单独申请支付宝商家资质），建议二期再说

### 2. "钱打到卡里"的前提是有营业执照

| 项目 | 个人主体 | 个体工商户 / 企业 |
|---|---|---|
| 注册小程序 | 可以 | 可以 |
| 开通微信支付 | **不可以** | 可以 |
| 餐饮类目 | **不可以** | 可以 |

**结论**：必须先办个体工商户营业执照（各地政务网线上办理，基本零成本），外加食品经营许可证（餐饮类目审核必需）。这一步绕不过去，建议现在就去办，它是整个项目的关键路径。

开通后：顾客付款 → 微信支付商户号 → **T+1 自动结算到你绑定的银行卡**。全程微信官方打款，不经过任何第三方账户，没有资金池风险。

### 3. "免费 + 永久稳定"两个词放一起不成立，但可以做到几乎不花钱

真实成本清单：

| 项目 | 费用 | 说明 |
|---|---|---|
| 个体工商户营业执照 | ≈ 0 元 | 政务网线上办 |
| 食品经营许可证 | 0–200 元 | 各地不同 |
| 小程序非个人主体认证 | 30 元 / 年 | 微信已从 300 降至 30，以提交时页面为准 |
| 微信支付商户号 | 0 元开户 | 按流水抽 **0.6%** |
| 微信云开发（后端+数据库+CDN） | **0 元起** | 免费额度日均 200 单内基本够用 |
| 域名 / 服务器 | **0 元** | 不需要，云开发自带 HTTPS 域名 |
| 云喇叭（可选，强烈建议） | 一次性 ≈ 200 元 | 飞鹅/易联云，彻底不漏单 |

**起步总成本：30 元 + 0.6% 交易手续费。** 超出免费额度后，云开发按量计费，日均 500 单规模大约每月 20–50 元。

> ⚠️ 提醒：市面上宣称"完全免费永久使用"的第三方点餐 SaaS，通常是首年免费次年收 2000–5000 元年费，或者你的订单数据、顾客数据握在对方手里，随时可能涨价、跑路或封号。自建方案虽然要花 30 块，但代码和数据 100% 是你自己的。

### 4. 提示音有个绕不过的坑，方案里做了双保险

**手机锁屏或 App 切到后台时，系统不允许小程序继续播放声音**——这是 iOS/Android 的操作系统限制，任何小程序都做不到。这也是为什么蜜雪、塔斯汀门店里用的都是专门的云喇叭/小票机。

三层兜底方案：

1. **商家端前台常驻**（免费）：后台页面开着时，新订单实时播报"您有新的订单"+ 震动 + 弹窗，这是最主要的场景（营业时间店员本来就盯着屏幕）
2. **微信订阅消息**（免费）：切到后台时，微信官方推送弹窗提醒，点击直达订单
3. **云喇叭 / 小票打印机**（一次性 200 元，**强烈建议**）：独立硬件设备，插电联网就响，不依赖手机状态，同时自动打小票。这是餐饮行业的标准做法

## 三、技术选型

### 核心决定：微信云开发 CloudBase（Serverless）

| 需求 | 云开发怎么解决 |
|---|---|
| 电脑不在线也能访问 | 代码/数据全在腾讯机房，与你的设备无关 |
| 不会崩、人多不卡 | Serverless 自动弹性扩容，腾讯运维 |
| 免费、不用买服务器 | 有永久免费额度，超出才按量计费 |
| 不用备案、不用买域名 | 云开发自带 HTTPS 域名和证书 |
| 新订单实时到达 | 数据库 `watch()` 原生实时推送，毫秒级，不用轮询 |
| 电脑端后台网页 | 静态网站托管，直接给出公网访问地址 |

**对比其他方案**：自建服务器需要买云主机（≥60 元/月）+ 域名 + 备案 + 自己运维扩容和安全，成本和心智负担都高一个数量级。对单店/连锁小店，云开发是明确的最优解。

### 各端技术栈

| 端 | 技术栈 | 部署方式 |
|---|---|---|
| 顾客端 | 微信小程序原生 + Skyline 渲染引擎 + TDesign | 微信小程序（独立 appid） |
| 商家端 · 手机 | 微信小程序（独立 appid，与顾客端隔离） | 微信小程序 |
| 商家端 · 电脑 | Vue 3 + Vite + TDesign Web | 云开发静态网站托管 |
| 商家端 · App（二期） | uni-app 打包 Android APK | 自行分发 / 应用商店 |
| 后端 | 云函数 Node.js + 云数据库 + 云存储 | 微信云开发 |

**为什么顾客端和商家端用两个独立 appid：**

1. 顾客端主包能压到 1.5MB 以内，冷启动更快（对扫码即用的场景至关重要）
2. 商家端审核出问题不会连累顾客端下线
3. 商家端可以用"未认证个人号"先跑内测，不阻塞进度
4. 权限天然隔离，顾客不可能误入后台

**为什么用 Skyline 渲染引擎：** 商家端的订单卡片左右滑动操作需要 60fps 的跟手体验，Skyline 的 worklet 动画在 UI 线程执行，不受 JS 线程阻塞影响。用传统 WebView 渲染在订单量大时会明显掉帧。

## 四、功能清单

### 顾客端（扫码即用，无需下载）

- **扫码进店**：二维码带门店 ID + 桌号，扫码直达对应门店菜单
- **公告弹窗**：进入时自动弹出商家公告（"今日草莓售罄"、"第二杯半价"）
- **打烊判断**：非营业时间显示打烊页 + 营业时间提示，无法下单
- **菜单浏览**：左侧分类锚点 + 右侧商品列表，图文卡片
- **规格与加料**：杯型/温度/糖度/加珍珠等多规格组合，实时算价
- **购物车**：底部悬浮购物车，数量增减，规格备注
- **优惠券**：领券中心 + 下单自动匹配最优券
- **配送/自提**：自提免运费，配送按规则算运费，支持起送价
- **微信支付**：一键唤起，支付失败可重新发起
- **取餐码**：支付成功大字号展示取餐码，状态实时刷新
- **订单历史**：历史订单、再来一单、申请退款
- **分享**：转发好友 / 分享朋友圈带门店参数

### 商家端（手机 + 电脑，同一套数据）

**订单看板（核心）**
- 四个状态页签：待接单 / 制作中 / 待取餐 / 已完成
- 新订单实时插入 + 语音播报"您有新的订单" + 震动 + 红点角标
- **卡片左右滑动操作**：右滑接单、左滑完成、长按更多（退款/备注/打印）
- 订单详情：商品明细、规格、备注、金额、支付时间、取餐码
- 历史记录查询：按日期/取餐码/手机号搜索

**商品管理**
- 分类增删改、拖拽排序
- 商品上架/下架/售罄（一键切换，顾客端秒级同步）
- 改价格、改原价（划线价）、改名称、改描述
- 图片上传（自动压缩 + WebP + CDN 加速）
- 规格组、加料组配置
- 库存管理（可选，售完自动下架）

**营销工具**
- 优惠券：满减券、折扣券、免运费券、新客券
- 发放方式：领券中心自领、下单赠送、扫码即得
- 有效期、发放总量、每人限领配置
- 满减梯度（满 20 减 3、满 50 减 10）
- 运费规则：起送价、基础运费、满额免运费

**营业设置**
- 营业时间段（支持跨天，如 10:00–02:00）
- **一键手动打烊 / 开业**（临时情况立即生效）
- 门店公告编辑（扫码进入时弹窗展示）
- 门店信息：名称、logo、地址、电话、公告
- 二维码生成与下载：门店码 / 桌码（1–N 号桌批量生成，可直接打印贴桌）

**数据统计**
- 今日营业额、订单数、客单价
- 7 日 / 30 日趋势图
- 热销商品排行
- 时段分布（几点单最多，指导排班）

**账号与权限**
- 老板 / 店长 / 店员三级角色
- 店员只能接单，不能改价和看营业额

## 五、数据模型

云数据库（文档型）集合设计：

| 集合 | 用途 | 关键字段 |
|---|---|---|
| `shops` | 门店配置 | name, logo, notice, businessHours, manualClosed, deliveryRule, freeShipAmount |
| `categories` | 商品分类 | shopId, name, sort |
| `products` | 商品 | shopId, categoryId, name, image, price, originPrice, specGroups, addonGroups, stock, onSale, sort, soldCount |
| `coupons` | 优惠券模板 | shopId, type, threshold, amount, validFrom, validTo, totalCount, limitPerUser |
| `user_coupons` | 用户已领券 | userId, couponId, status, usedOrderId |
| `orders` | 订单 | shopId, pickupCode, userId, items(快照), amountDetail, payInfo, status, timeline, tableNo |
| `users` | 顾客 | openid, nickname, phone, lastOrderAt |
| `staff` | 商家账号 | shopId, openid, role, name |
| `counters` | 取餐码计数器 | shopId + date 复合唯一，seq |

### 订单状态机

```
pending_pay ──支付成功──> paid(待接单) ──商家右滑──> accepted(制作中)
                              │                          │
                              │                    商家左滑│
                              │                          ▼
                              │                    ready(待取餐)
                              │                          │
                              │                     顾客取走│
                              │                          ▼
                              │                     completed
                              │
                        ──超时/退款──> cancelled / refunded
```

### 关键技术实现要点

1. **取餐码生成**：云函数内用 `counters` 集合做原子自增（`_.inc(1)`），按 `shopId + 日期` 分组，格式 `A001`–`A999`，每天 0 点自然重置。**必须用数据库原子操作，前端生成或读取后加一都会在并发时重号。**

2. **实时同步**：商家端用 `db.collection('orders').where({shopId, status: _.in(['paid','accepted','ready'])}).watch()`，服务端主动推送变更，毫秒级到达，不消耗轮询请求。顾客端同样 `watch` 自己那一单，状态变化自动刷新。

3. **语音播报**：小程序端用 `InnerAudioContext` 播放预置 mp3；网页端用 Web Audio API + Notification API。多单同时到达时做队列串行播报，避免声音叠加。

4. **滑动操作**：Skyline `worklet` 手势 + `shared value`，滑动跟手在 UI 线程完成，松手回弹用 spring 动画。设置滑动阈值 + 二次确认，防止误触。

5. **二维码生成**：云函数调 `wxacode.getUnlimited`，`scene` 参数传 `shopId_tableNo`（限 32 字符，用短 ID），生成后存云存储，后台可直接下载打印。

6. **打烊校验**：营业状态判断**必须在云函数里做二次校验**。只在前端判断，技术上可以被绕过直接调接口下单。

7. **支付幂等**：`outTradeNo` 建唯一索引，支付回调做幂等处理，防止微信重复回调导致订单重复入账。

8. **金额计算**：**所有价格用「分」为单位的整数存储和计算**，绝不用浮点数。优惠、运费、总价的最终计算全部在云函数完成，前端只做展示，防止客户端篡改金额。

9. **性能**：商品列表云函数结果缓存 5 分钟；图片走 CDN 并按需生成缩略图；商家端订单列表用虚拟列表，历史订单分页加载。

## 七、上线合规清单（避免审核被拒）

- [ ] 服务类目选择「餐饮服务 → 餐饮服务场所」，需上传营业执照 + 食品经营许可证
- [ ] 小程序后台配置《用户隐私保护指引》，声明收集的信息（手机号、位置）及用途
- [ ] 所有 API 域名加入 request 合法域名白名单（云开发默认已加）
- [ ] 首页不得强制登录，必须能先浏览菜单再登录下单
- [ ] 获取手机号、位置权限前必须有明确的使用场景说明
- [ ] 文案避免「最」「第一」「国家级」等广告法违禁词
- [ ] 商品图片不得使用未授权的网图（用自己拍的或正规图库）
- [ ] 提审时提供测试账号和完整的操作路径说明
- [ ] 主包体积控制在 1.5MB 以内（图片全部走 CDN，不打包进小程序）

不在一期范围，但架构已预留：

- **视频号联动**：直播间挂小程序链接引流到店

## 九、需要你现在确认的 3 件事

1. **营业执照现在有吗？** 有 → 直接开工；没有 → 今天就去当地政务服务网办个体工商户，这是唯一的硬阻塞项。

2. **一期做单店还是多店？** 单店最快，架构已预留多店扩展，后面加不用重写。

3. **商家后台先做小程序还是先做电脑网页？** 建议：手机小程序优先（店里主要用手机接单），电脑网页第 3 周补上，App 打包放二期（iOS 上架需要 688 元/年开发者账号，且审核周期长，不值得在一期投入）。
